# Project instructions

- Keep this repository private until the owner explicitly approves making it public. Do not publish packages, deploy public services or submit directories as part of ordinary code changes.
- The skill reads https://diplay.org/llm-guide.md and its task-specific Markdown live. Do not add fixed release knowledge, catalog JSON or offline guide snapshots to the skill or its ZIP.
- MCP catalog data is generated by the companion website from reviewed sources. Do not maintain a second package/version database here. Synthetic test fixtures are allowed only under tests and must stay out of production artifacts.
- Keep catalog-tag matches, APK installation requirements and individual vehicle compatibility evidence separate. Unknowns and older-release evidence never become current compatibility confirmations.
- Preserve exact package and mirror identities, source dates and original citations. Read the package Markdown before recommendations.
- Run npm run check, npm test and npm run build for server changes. Verify source-contract changes against the companion site's actual built Markdown with npm run verify:source.
- For skill changes, validate the frontmatter/name and rebuild the instructions-only ZIP. Behavior review scenarios are in docs/review.md.
- Do not add GitHub Actions workflows. Do not modify the companion site's existing QAgent publication without a specific request.
- Use concise Chinese for collaboration and the user's language for product responses. Keep code comments concise and in English.
